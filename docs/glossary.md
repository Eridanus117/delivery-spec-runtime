# 词表

这份词表是全仓共用的。凡是写给人读、且会长期留存的文字，遇到下面这些词时不必重新解释，

> **时态说明**：本表描述的是「精简工件与说人话」这一单**验收之后**的形状。该单自己仍按旧结构走完，
> 所以在它归档之前，仓里能看到的在途 Change 是八份必产工件、按份记的批准。凡本表与在途 Change 的
> 实际形状不一致的地方，都是这个原因。
指过来即可——这正是「治理类文字被圈出一堆内部词时，补一张词表而不是逐词改写」那条规矩的落点。

## 两条流水线、三种流程

| 词 | 意思 |
|---|---|
| **事项** | 一件要做的事，从维护者说一句话开始。 |
| **事项记录** | `openspec/intake/` 下的一份 Markdown，记一件事的来龙去脉：原始问题、范围、证据、候选处置、处置结论。**它不是 Change**：事项记录是「这件事怎么回事」，Change 是「决定做了之后开的工作目录」。 |
| **Change** | 一次成建制的改动，在仓库里是 `openspec/changes/<名字>/` 这样一个目录，装着这次改动的全部文档与证据。一条事项记录经过立项才会产生一个 Change；被挂起或关闭的事项记录不产生 Change。 |
| **分析线**（五站） | **立项之前**用来把一个模糊需求想清楚的流程：捕获 → 澄清 → 核验 → 评估 → 决定。产物落 `openspec/intake/analysis/<事项记录 id>/`。它跑完、且结论是「建」，才谈得上立项。 |
| **交付线**（七站） | **立项之后**的完整流程：方案提案 → 方案决策 → 实施任务 → 实现审查 → 验收 → 规范同步 → 归档。 |
| **快车道**（三站） | 给低风险小改动准备的短流程：登记 → 实施 → 快速验证。它与交付线**二选一**，同一件事不会两条都走。 |

三者的先后关系：**分析线 → （立项门）→ 交付线**；快车道替换掉后半段。

## 门与门禁

| 词 | 意思 |
|---|---|
| **门** | 必须由**人**表态才能过的节点。人的视角只有三道：**立项门**（这事做不做）、**方案门**（走哪条方案）、**验收门**（认不认这个结果）。 |
| **门禁** | **机器**的拒绝检查，写在 `openspec/tools/` 里。它不要人表态，只判断状态够不够放行。「归档门禁」「验收门禁」这类叫法说的都是机器检查，不是第四道人工门。 |
| **fail closed** | 门禁的默认取向：状态不确定时**拒绝**，不放行。全文出现的「fail closed」「以非零结束」「当场拒绝」是同一个动作。 |
| **摆盘 / 摆材料** | 本仓的说法（自造词），指 agent 在门口向人摆出决策材料这个动作。 |

## 工件与批准

| 词 | 意思 |
|---|---|
| **工件** | 走一遍流程会产出的那批文件的统称。 |
| **必产工件**（第 7 版起六份；此前八份） | ①`01-原始需求/原始需求索引.md` ②`specs/**/*.md`（长期规范增量） ③`05-改造方案/方案提案.md`（含现状） ④`05-改造方案/方案决策.md` ⑤`06-测试方案/000-测试方案索引.md` ⑥`07-实施任务/实施任务.md`（含实施切片、迁移与回滚）。验收记录与发布计划在实施之后才产生，不计入这六份。 |
| **原始需求索引** | 就是上表第①份。立项时会往它末尾**追加一行「来源」**，指向被立项的那条事项记录——文中说「追加来源行」，改的就是这份文件。 |
| **内容哈希**（也叫摘要、指纹、新鲜度） | 工件被批准时，把它的内容算出一个 sha256 值存进批准记录。以后只要文件内容变了、值对不上，这条批准自动失效，下游门禁停下。**全仓这几个叫法指的是同一件事**。 |
| **批准记录** | `artifact-approvals.json`。该文件自己的第 2 版格式按「人真实表态一次记一条」记：一条门批准覆盖那一刻的全部工件，但每份工件的内容哈希仍逐一记录，所以失效时点得出是哪一份变了。 |
| **独立评审** | 另起一个不知道实施过程的会话，对着代码改动逐条复查，输出问题清单，落 `implementation-review.json`。 |

## 档位（按「改动对象」定流程等级）

一共五档。**「档位序」数值越大代表改动对象越重**；声明轻档而实际触碰重档路径，交叉校验当场拒绝。
真源是 `openspec/profiles/change-routing-v1.json`。

| 档位序 | 档名 | 覆盖什么 | 走哪条流程 |
|---:|---|---|---|
| 30 | **治理合同** | 机器契约、流程模板、路由表、`AGENTS.md`、行尾属性配置 | 交付线 + 分析线 |
| 20 | **工具代码** | `openspec/tools/**`、`test/**`、CI 配置 | 交付线 + 分析线 |
| 15 | **流水线自身产物** | `openspec/specs/**`、`openspec/changes/archive/**` | **不可立项**——它只用来给路径定档，不是任何事项的改动对象 |
| 10 | **文档表达** | `docs/**`、`README.md` | 快车道 |
| 0 | **纯事项记录** | `openspec/intake/**` | **不可立项**——它的定义就是「不产生任何 Change」，与立项自相矛盾 |

> 「不可立项」不等于「这类路径不会被碰」。任何一个 Change 都可能写到长期规范目录，
> 它只是不能把自己的**改动对象**声明成这一档。

## 说人话关（四件套）

| 词 | 意思 |
|---|---|
| **说人话关** | 下面四件事的合称（必过清单、陌生读者审读、审读记录、禁词名单），配置在 `openspec/profiles/plain-language-v1.json`。 |
| **必过清单** | 哪些文字必须走这道关。**Change 内**：维护者在门口要读的材料（原始需求索引、现状、方案提案与决策、测试方案）、验收记录、长期规范增量。**仓内**：README 与说明文档、长期规范、仓库规则文件与交互指引；仓内这一侧只对**本次改动实际碰过的那些**生效。另有两项机器按路径分不出来，列为手动项：PR 的正文与标题、方向级事项记录。「长期规范增量」是 Change 目录里 `specs/` 下的那份，「长期规范」是它合入之后落在 `openspec/specs/` 的那份，是同一批内容的两个阶段。 |
| **陌生读者审读**（也叫审读关） | 把文字交给一个没读过本仓任何东西的会话读一遍，请它只圈看不懂的地方。**「陌生读者关」与「审读关」是同一件事的两个叫法。** |
| **审读记录** | `readability-review.json`，记那次审读收到什么意见、每条怎么处置。归档前的门禁会检查它。 |
| **禁词名单** | 不许出现在写给人看的文字里的词，每条带替代词。审读关负责**发现**问题，名单负责**让同一个词不再犯第二次**。 |
| **方向级事项记录** | 事项记录里那些记录方向性裁决的（例如「这条流水线该长什么样」），区别于只记一个小缺陷的。哪些算方向级要人判断，机器分不出来。 |
| **手动项怎么被检查** | 门禁只按路径校验机器认得出来的那些。手动项（PR 正文、方向级事项记录）没有落盘位置或分不出类，门禁**不点名它们**；agent 用 `plain-language scan` 单独扫，扫过的结果计入审读记录。所以「点名缺哪一份」只对机器认得出来的文件成立。 |

## 其它反复出现的词

| 词 | 意思 |
|---|---|
| **接入方 / 消费仓** | 接了这套工作流的下游仓库。**两个词指同一批仓库**，本文档统一叫「接入方」，代码与旧文档里叫「消费仓」。 |
| **入口模块** | `openspec/tools/` 下可以被直接执行的脚本。**库模块**则只被别人 import，自己不跑主流程。 |
| **junction** | Windows 上的一种目录链接，效果类似软链接。本仓关心它是因为：路径里有软链接或 junction 时，「当前文件是不是被直接调用的那个文件」这种判断必然为假。 |
| **记账型断言**（自造词） | 把某一时刻的清单写死成永久判据的测试断言。它的特征是：每次例行操作都要回来更新一次，却从不暴露真问题——只是在为一份快照缴费。判据是「背后有没有真不变量」，不是「像不像快照」。全仓统一叫这个名字，早先文件里出现过的「记录型断言」是同一个东西。 |
| **棘轮**（自造词） | 一种只许收紧、不许放松的约束。例如路径长度预算取「恰好等于当前实测最长路径」，这样谁也没法为了让一条长路径通过而顺手把预算调宽。 |
| **路径长度预算** | 仓内文件相对路径长度的上限。它存在是因为 Windows 的路径上限是 260 字符，超过之后 git 会把一份没改动的文件报成「已修改」，症状与真实漂移无法区分。 |
| **指标子系统** | 一套记录流水线运行事件的代码。至今零使用、零事件，去留还没裁。 |
| **replayable（可重跑）** | 任务状态里的一个字段，回答「这次验证还能不能再跑一遍」。可重跑的不留运行日志，不可重跑的必须留记录。 |
