## 原始问题

用户询问：一个需求进入后应如何处理，需求分析是否需要做，以及分析应放在 Change 内还是 Change 外。

## 可核验观察

- 该问题本身是流程咨询，不包含明确的代码实施请求。
- 本次处理直接创建并完成了 `establish-workflow-multi-profile-v01` Change。
- 该 Change 实际包含 Runtime 自托管 OpenSpec 流程、多 Workflow Profile contracts/core/CLI、测试、文档、Acceptance、Spec Sync 和 Archive。
- 最终实现已通过验证并归档，但实际工作范围明显大于回答流程边界所需的最小范围。

## 影响与当前边界

- 影响：流程咨询与实施请求之间缺少明确确认点，可能导致 Agent 在用户未要求实施时扩大 Change 范围和时间成本。
- 本 Intake 只记录 Runtime 项目的需求入口和范围判断问题，不修改已归档 Change 的功能结论，也不要求新增业务 Workflow。
- 该问题属于本仓库范围：它直接影响 Runtime 自身如何接收、分析和决定 Change；不涉及消费仓业务需求或私人资料。

## 当前处置

- 已在本次会话中识别并确认根因：将流程咨询误判为实施请求。
- 后续默认行为：流程咨询先输出现状、边界和建议；只有用户明确要求落地或明确确认实施范围后，才创建/修改 Change。
- 进入实施前先确认最小交付范围；实施后再按正式 Change 生命周期执行。
- 当前不创建新的 Change；本条保持 `triaged`，作为后续流程改进的入口。
