# Intake

## 原始问题

评审流程两条教训，由本单终审代理自报：其一，评审期间不得在被审工作树上并发跑会写盘的代理——被审对象在评审过程中被改动，评审结论就失去了它所绑定的那个快照；其二，做变异验证时还原文件要按字节回拷，不能用 git checkout，因为工作树的换行符归一化会让回拷后的文件与原文件不逐字节相同，这在本仓已有前科。

## Triage

范围：独立评审这个动作本身的做法约束——评审期间工作树怎么用、变异验证怎么还原。
不含：评审要查什么、评审记录写什么（那些已有长期规范）。本条只管操作方式。
影响：只改说明面（评审者指引与仓库规则），不碰任何机器可读约束。
判断：continue——两条都是本单终审代理自己踩过并自报的，代价小、收益直接。

## Evidence

### 已知事实

- **评审期间不得在被审工作树上并发跑会写盘的代理。** 评审结论绑定的是一个快照；被审对象在评审
  过程中被改动，那个结论就失去了它所指的东西，而机器在评审记录写入之前不会发现。
- **变异验证的还原要按字节回拷，不能用 `git checkout`。** 工作树的换行符归一化会让回拷后的文件
  与原文件不逐字节相同，于是内容哈希对不上、一堆记录莫名转过期。本仓已有前科：`.gitattributes`
  只对 JSON 强制统一行尾，其余文件按平台走，Windows 上尤其明显。
