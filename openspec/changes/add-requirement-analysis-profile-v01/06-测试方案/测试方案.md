# 测试方案

## 合同测试

- profile schema 接受新可选字段并拒绝重复、未知或不一致的 judgment 配置。
- registry 列出 `requirement-analysis@v1.0.0` 及五阶段 `capture`、`clarify`、`discover`、`evaluate`、`decision`。

## 核心行为

1. capture 缺少 request 时 blocked；输入完整时推进 clarify。
2. clarify、discover、evaluate 分别缺少 `problemFrame`、`capabilityReport`、`optionReport` 时 blocked。
3. 任一分析阶段 + `continue-analysis` 返回当前阶段、下一阶段均为当前阶段，且不伪造完成。
4. 三个分析阶段依次 + `sufficient` 推进下一个阶段，并最终进入 decision。
5. decision 缺少人工判断时 waiting；四类合法处置分别 completed，并投影完整分析链、decision、disposition、candidateProfileId。
6. 非法 judgment 被拒绝或不能完成阶段。
7. 既有 light-change 和 delivery-change 测试全部回归通过。
8. CLI 通过显式 binding 执行，不修改 Desk 或调用方以外资产。
