# 方案决策

## 决策状态

- 状态：APPROVED
- 选择：候选 A，扩展通用 stage 合同并新增 `requirement-analysis@v1.0.0`
- 决策人：Runtime 维护者
- 决策时间：2026-08-30

## 决策依据

- 需求分析循环是公共 Workflow System 可复用的阶段语义，但 Desk 的个人策略仍留在 Desk。
- 通过可选 stage 字段表达循环和结果投影，不影响既有 profile 的默认线性执行。
- `capture → clarify → discover → evaluate → decision` 把原始陈述、问题边界、现有能力、候选方案和门 B 决策拆成可审计阶段，不再把全部分析压缩为单点 `analysis`。
- 输出返回完整分析链与处置，不自动创建 Change 或写入外部资产。

## 接受的后果

- 各阶段分析报告的累积和事项归属由调用方保存；Runtime 不提供持久化。
- `continue-analysis` 是当前阶段重复，不是任意图工作流；更复杂的回退和分支另立 Change。
- 需求分析 profile 的 `build` 结果仍需调用方显式创建并绑定后续 Change。
