# 业务现状

## 当前问题

Runtime 目前能列出、绑定和执行 profile，但现有 `delivery-change` 偏重，`light-change` 只覆盖已捕获事项的轻量实施。两者都不能表达“先澄清问题，再核验现有能力、比较方案，逐轮补证据，最后由主人决定是否建设”的完整前置流程。

## 使用场景

- 没有完整外部产品需求输入的事项，需要先澄清真实问题、目标、范围和约束，再分析现有能力、收益和成本。
- 分析由多个相互衔接的阶段组成，可能需要多轮普通对话和事实核验；分析师不能替主人判断任一阶段证据是否足够。
- 证据充分后，主人在门 B 决定建设、使用现成能力、暂缓或拒绝。

## 范围边界

本 Change 只交付公共的需求分析 profile 和可机器执行的阶段合同。Desk 的个人策略、具体事项内容、工作区索引、自动路由、自动建 Change 和建成后的门 C 复盘不属于本 Change。

## 业务不变量

1. 分析报告必须能由人审阅，包含已知、未知、证据状态和置信度。
2. 分析充分性和门 B 决策属于资源持有人，Agent 只能准备产物。
3. `build` 只产生可供调用方后续建 Change 的结果，不越权建 Change。
4. Profile 必须能脱离 Desk 独立运行。
