# 技术现状

## 已有能力

- `openspec/intake/INT-20260830-005-metrics-concurrency.md` 已记录指标范围、事件字段、存储边界、计算口径和首轮实验门槛。
- Runtime 已有 `workflow-core.ts`、Profile 合同、结果合同和 `workflow-entry.ts` standalone 执行入口。
- Runtime 已有严格的路径守卫、公共资产白名单和合同测试约束。
- `runtime-entry.ts` 和 `intake-control.ts` 可以提供结构化 CLI 结果，但当前没有通用 workflow 指标采集器。

## 技术缺口

- 没有统一的 metrics event schema、写入器、去重和损坏检测实现。
- Runtime 无法直接读取 Agent 调度器的真实 `slotCount` 和 `activeCount`。
- 没有本地私有 state 目录的跨平台解析、保留和清理实现。
- 没有基线汇总器或 `C+1` 对照报告生成器。

## 约束

- TypeScript 使用 `node --experimental-strip-types`，测试使用 Node 内置 `node:test`。
- 公共 Runtime 不保存真实业务事项、请求响应、凭据、绝对路径、机器标识、trace 或可逆标识。
- 采集失败必须 fail closed，不能静默降级为不完整成功记录。
- 新 Runtime 行为必须通过本 Change 的批准、实现、Review、Acceptance、Spec Sync 和 Archive 生命周期交付。

## 实现方向

优先实现可独立验证的事件合同和本地追加写入边界，再实现汇总与对照报告；不在本 Change 中实现 Agent 调度器或自动提高并发。
