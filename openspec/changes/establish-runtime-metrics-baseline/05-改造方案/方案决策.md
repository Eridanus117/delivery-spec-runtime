# 方案决策

## 决策状态

- 状态：APPROVED
- 选择：候选 B：Runtime 本地记录与汇总
- 决策人：Runtime 维护者
- 决策时间：2026-08-30
- 权威来源：维护者明确选择候选 B

## 决定

实现标准化 metrics event contract、本地私有追加写入、敏感内容与路径守卫、重复事件拒绝、损坏检测、汇总和 C/C+1 对照报告。

## 明确边界

- 不建设远程 telemetry、数据库、组织级看板或跨仓同步；
- 不自动修改 Agent 调度器配置，不自动提升长期并发；
- 不记录业务正文、请求响应、账号、凭据、绝对路径、机器标识、trace 或 release-id；
- Agent 调度器不提供 `activeCount` 时报告缺失，不以 `slotCount` 猜测实际并发；
- 真实原始事件只存在运行者本地私有 state 目录，公共 Runtime 仓只保留 schema、合成样例和审查汇总。

## 新确认

- 维护者确认本轮目标 workflow 的指标均可观测，包含实际 `activeCount`；
- 基线采集应直接记录调度器提供的 `activeCount`，不需要为本轮新增调度器适配层；
- schema 仍允许 `activeCount: null`，仅用于未来确实无法观测的调用方，不得在本轮主动使用缺失值。

## 执行范围决定

- 所有可观测 workflow 均纳入采集，但按 Profile 分别汇总，不混合成单一基线；
- 每个 Profile 使用 10 个满足资格的事项，最长 5 个工作日，至少 8 个可计算完成事项；
- 先完成当前并发 `C` 基线，再由人工依据门槛决定是否执行 `C+1`。

## 拒绝方案

- 候选 A：仅使用手工模板；人工漏记和口径漂移无法满足 C/C+1 的稳定比较；
- 远程 telemetry、自动调度和自动提高长期并发；超出本 Change 的隐私和风险边界。

## 选择依据

- 标准化是 C/C+1 可比性的前置条件，脱敏是隐私和公共仓边界，不混淆两者。
- 手工模板可以快速试跑，但人工漏记和口径漂移会削弱实验可信度。
- Runtime 受控记录器可以用机器合同验证字段完整性、敏感内容边界、重复事件和汇总公式，同时保持本地、低频和可逆。

## 接受的后果

- 首版不提供组织级实时看板或跨仓历史查询；
- 首轮结果是探索性证据，不等同于统计显著性或长期并发策略；
- 需要调用方显式提供真实运行上下文，Runtime 不猜测 Agent 调度状态。

## 重新决策触发条件

- 首轮数据表明当前协议无法区分主要等待、冲突或返工原因；
- 本地存储无法满足隐私、完整性或清理要求；
- 需要跨仓汇总、远程上传或自动调度；这些都必须重新扩大 Change 范围并重新决策。
