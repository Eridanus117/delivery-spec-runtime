# 业务现状

## 当前问题

Runtime 已提供 Intake、Profile workflow、Change、Review、Acceptance 和 Archive，但缺少证据判断流程是否提高有效决策完成率，以及并发增加是否降低等待而不增加冲突、返工和质量成本。

## 当前目标

先在低频真实运行中记录当前并发 `C` 的基线，再决定是否值得用 `C+1` 做单变量对照。目标是获得可解释的效率证据，不是立即提高并发，也不是建设组织级 telemetry。

## 当前边界

- 真实事件数据属于运行者本地私有工作区；公共 Runtime 仓只保留协议、合成示例和审查后的汇总。
- 业务结果的“有用”由人工判断，不由指标工具猜测。
- `C+1` 只作为实验变量，不自动变成长期配置。
- 评估重点是吞吐、首次有用产出时间、排队、WIP、冲突、返工、质量门禁和数据完整率。

## 成功结果

- 同一事件合同可以记录一批可比较的运行；
- 可以明确区分排队时间、执行时间和首次有用产出时间；
- 可以在不暴露业务内容的情况下形成 `C` 汇总；
- 只有满足预设样本和护栏条件，才会考虑 `C+1`；
- 样本不足或数据不完整时明确输出“无法判断”。
