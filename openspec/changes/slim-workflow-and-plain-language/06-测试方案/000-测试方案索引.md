# 测试方案索引

> **本方案不产出任何运行日志。** 按维护者在方案门给的新判据：本仓的验证全部是可重跑的自动化测试，
> 要复核就当场重跑一遍，存下来的日志无法证明它对应的是当前这版代码。验收记录只保留结论性数字
> （跑了多少项、过了多少项）。

## 测试层级

只有一层：Node 内置测试跑 `test/*.test.ts`。不新增任何 shell runner，不引入外部测试框架。
运行方式固定为 `node --experimental-strip-types --test test/*.test.ts`。

## 失败即停条件

任一断言失败、`openspec validate --strict` 非零、命令渲染出现漂移、接入检查非零——四者任一发生
即停止推进，不得靠重跑几次把它跑过去。

## 场景与断言

每个编号对应一个实施切片，编号被实施任务表与验收覆盖表逐条回引。

### T-01 说人话关

| 断言 | 形态 |
|---|---|
| T-01.1 | 禁词出现在必过清单命中的文件里 → 校验失败并点名是哪个词、哪个文件、第几行 |
| T-01.2 | 同一个词出现在豁免范围的文件里 → 校验通过（证明作用范围是按清单裁的，不是全仓一刀切） |
| T-01.3 | 必过清单里的某份文件没有审读记录 → 验收前的门禁拒绝并点名缺哪一份 |
| T-01.4 | 审读记录里有一条意见没有处置结论 → 拒绝并点名是哪一条 |
| T-01.5 | 审读记录齐备且无禁词 → 放行 |
| T-01.6 | 禁词单与必过清单的配置文件结构不合法 → 加载时即失败，不静默降级为「不检查」 |

### T-02 入口守卫

| 断言 | 形态 |
|---|---|
| T-02.1 | 全部入口模块的源码里都不出现基于路径比较的执行守卫（`import.meta.filename` 或 `process.argv[1]` 判据） |
| T-02.2 | 全部入口模块都不导出任何符号 |
| T-02.3 | `openspec-upgrade` 的报告校验函数从库模块导入后仍能拒绝残缺报告（证明挪位置没有把校验弄丢） |

### T-03 立项门与敏感内容

| 断言 | 形态 |
|---|---|
| T-03.1 | 立项门因内容检查而拒绝时，事项记录文件与目标 Change 的原始需求索引都逐字节不变 |
| T-03.2 | 事项记录里写一个网址 → 放行 |
| T-03.3 | 事项记录里写一个本机盘符绝对路径 → 仍然拒绝 |
| T-03.4 | 网址与盘符路径同时出现 → 拒绝（放行网址不得连带放行盘符） |

### T-04 评审范围

| 断言 | 形态 |
|---|---|
| T-04.1 | 实施提交里包含对 `openspec/specs/**` 的改动时，该路径出现在评审记录的被审路径中 |
| T-04.2 | Change 目录自身仍被排除（它是治理产物，不是实现改动） |

### T-05 证据新规则

| 断言 | 形态 |
|---|---|
| T-05.1 | `replayable: true` 的任务保存了证据路径 → 拒绝，理由指向「可重跑的验证不留日志」 |
| T-05.2 | `replayable: false` 的 `verified` 任务没有证据路径 → 拒绝 |
| T-05.3 | `replayable: false` 且有证据 → 原有的路径逃逸与非空校验一条不少地仍然生效 |
| T-05.4 | 存量任务状态没有 `replayable` 字段 → 仍可读出，按可重跑处理 |
| T-05.5 | 新写入不带 `replayable` → 拒绝（不让默认值替人作判断） |

### T-06 工件结构第 7 版

| 断言 | 形态 |
|---|---|
| T-06.1 | 声明第 7 版的 Change：六份工件齐备即通过；缺任一份即拒绝 |
| T-06.2 | 声明第 7 版的 Change 里存在 `03-现状/` 或 `05-改造方案/改造方案.md` → 不被当作工件，不参与批准 |
| T-06.3 | 声明第 6 版、第 5 版与未声明的存量 Change 仍按各自的表解析，行为逐字节不变 |
| T-06.4 | 新建 Change 一律显式写入第 7 版 |
| T-06.5 | 第 7 版的方案提案模板含「现状」章节，实施任务模板含「实施切片、迁移与回滚」章节 |

### T-07 批准记录第 2 版

| 断言 | 形态 |
|---|---|
| T-07.1 | 一条方案门批准覆盖当时全部工件，实施门禁放行 |
| T-07.2 | 覆盖范围内任一工件事后被改动 → 该门批准失效，且报错**点名是哪一份变了** |
| T-07.3 | 覆盖范围缺任一工件 → 拒绝并点名缺哪一份 |
| T-07.4 | `schemaVersion: 1` 的存量批准记录仍按旧口径解析，行为不变 |
| T-07.5 | 两种口径不得混写进同一个文件 |

### T-08 站位与批准清单一致、探针补强

| 断言 | 形态 |
|---|---|
| T-08.1 | 需要人工批准的门，由站位定义里 `humanJudgment` 为真的站推导，不另立第二份清单 |
| T-08.2 | 单边改动站位定义 → 一致性检查失败并列出分叉的站名（既有 VC-002，保持） |
| T-08.3 | **七站全部**做真负向对照：抹掉该站的人工表态字段后重跑真门禁，取值只来自退出码 |
| T-08.4 | **探针活性对照**：故意破坏该站的一个机器前提，该站必须非零——证明探针确实跑到了真逻辑，而不是因为别的原因恰好返回 0 |
| T-08.5 | 一致性测试内部仍不得出现第二份「哪些站要人表态」的硬编码清单（既有 VC-003，保持） |

### T-09 记录型断言

| 断言 | 形态 |
|---|---|
| T-09.1 | 在途 Change 目录的断言改为不变量形态：不再锁死目录清单，改为「两个早期目录不在其中」加「每个在途目录都有合法的 Change 基本信息」 |
| T-09.2 | 新建或归档一个 Change 后，该断言不需要任何改动即仍然通过 |
| T-09.3 | 路径长度预算断言保持原强度（它背后有真不变量），并在注释里写明这个判断 |

### T-10 文档与交互指引

| 断言 | 形态 |
|---|---|
| T-10.1 | 「通用核心 vs 本仓特有」文档存在，且含证据记录那条差异 |

| T-10.3 | 说明文档不再提到已取消的两层工件 |

## 数据准备

全部用临时目录里现造的最小 Change 与最小 git 仓库，不依赖仓内真实数据；已有的
`test/helpers.ts` 提供建树与调用工具的入口，沿用不改。

## 运行环境

Node 由 `runtime-manifest.json` 声明最低版本；TypeScript 直接由 `--experimental-strip-types` 执行。
自动验证只在 ubuntu 上跑，Windows 侧由维护者本机实测；因此新增的检查必须在两个平台都给出确定判据，
不得靠「重跑几次都过」。

## 清理

每个用例自建临时目录、结束即删（沿用 `removeOptions` 的重试删除，避开 Windows 上的短暂持锁）。
测试不得在仓库工作区留下任何文件。
