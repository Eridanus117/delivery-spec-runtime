# 改造方案

> **这一层是最后一次出现。** 本单要做的事情之一就是把「改造方案」并进「实施任务」；新结构在本单
> 验收之后才生效，所以本单只能按现行结构走完。**本文件是本仓最后一份独立的改造方案。**
> 同理，`03-现状/现状.md` 也是最后一份独立的现状文档。

## 目标

1. 把八份必产工件压成六份：现状并进方案提案，改造方案并进实施任务。测试方案不并。
2. 批准记录从「一份工件一条」改成「人真实表态一次记一条」，一单两条（方案门一条在
   `artifact-approvals.json`，验收门一条就是 `acceptance-state.json`）。
3. 立起「说人话关」：必过清单 + 陌生读者审读记录 + 门禁校验 + 人话禁词单。
4. 按新判据处置证据：可重跑的验证不留运行日志，不可重跑的验证必须记录。
5. 修掉五处挂账缺陷，外加立项时新撞到的两处。
6. 把记录型断言按「背后有没有真不变量」逐条处置。
7. 把「通用核心 vs 本仓特有」写成一份文档。

## 非目标

- 不迁移已归档的 Change，不删它们的证据日志。
- 不动评审记录与验收状态的强校验（自算范围、四项新鲜度）。
- 不新造「由工具派发无上下文会话」的能力。
- 不改路由表（本单第一个动作已经改完）。
- 不处置指标子系统的去留（仍是开放问题）。

**批准记录（第 2 版）**

```
artifact-approvals.json
{ schemaVersion: 2,
  gates: { plan: { decision, approvedBy, approvedAt, migrationSource,
                   artifacts: { <工件名>: <该工件当时的内容哈希> } } } }
```

一条记录覆盖方案门当时已写完的全部工件，**每份工件的哈希仍逐一记录**，所以「改了哪一份就失效、
并且能点名是哪一份」的能力一份不丢。验收门那条不在这个文件里，它就是 `acceptance-state.json`。

**说人话关**

```
openspec/profiles/plain-language-v1.json    ← 必过清单、豁免清单、禁词单
<Change 根>/readability-review.json          ← 审读记录：每份必过文件一条，每条意见带处置结论
```

门禁在验收前校验：必过清单里的每一份都有审读记录、每条意见都有处置结论、且全部人读文字不含禁词。

**证据**

任务状态里每个任务新增一个字段 `replayable`（这次验证能不能再跑一遍）：

- `replayable: true` → **不得**保存任何证据路径。可重跑就当场重跑，存下来的日志无法证明它对应
  当前这版代码。本仓全部任务都是这一类。
- `replayable: false` → **必须**保存证据路径。做完就没了的验证，这是唯一一次机会。

## 兼容策略

- **已归档的 Change 一律只读兼容，不迁移。** 工件路径表按各 Change 自己在 `change-info.json` 里
  声明的版本取：没有声明的按第 5 版，声明 6 的按第 6 版，声明 7 的按第 7 版。这是已有机制，
  本单只是往里加一张表，**不新增兼容层**。
- **批准记录同理**：文件里 `schemaVersion: 1` 按旧口径（一份工件一条）解析，`2` 按新口径。
- **任务状态**：`replayable` 缺省视为 `true`（可重跑），因此存量任务状态不需要改写；但**新写入
  必须显式声明**，避免默认值把「这次验证到底能不能重跑」这个判断悄悄替人做掉。
- **禁词单只作用于今后产出的文字**，不回溯扫描存量文件。

## 迁移顺序

1. 先落 1–5 这五个互不依赖的切片，每片自带断言，逐片提交。
2. 再落 6（工件结构），此时旧结构仍可解析，本单自己仍按旧结构走。
3. 再落 7（批准口径），它要读工件路径表，所以在 6 之后。
4. 8、9 依赖前面的形状确定。
5. 最后落 10，把文档与交互指引对齐。

## 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 工件路径表变成第三张，读旧目录时选错表 | 版本判别只认 `change-info.json` 的显式声明，不靠目录形状推断（已有机制）；断言逐版本各跑一遍 | 该切片独立提交，直接 revert |
| 批准新口径把「能点名哪份变了」的能力弄丢 | 每份工件的哈希仍逐一记录；失效时的报错必须点名具体工件，断言守住 | 同上 |
| 取消证据后，`verified` 缺少可校验的支撑 | `verification`（怎么验证的）仍必填；`replayable: false` 时 evidence 仍强制且仍走原有的路径逃逸校验 | 同上 |
| 去掉入口守卫后，模块被 import 时产生副作用 | 前置动作是先把被测试引用的校验函数挪进独立库模块，入口模块不再导出任何符号 | 同上 |
| 禁词单误伤（比如引用维护者原话时必须出现该词） | 禁词检查只作用于今后产出的人读文字；引用原话属于存量转录，写在事项记录里，不在必过清单范围内 | 调名单，不关检查 |
| 一次改动面过宽，评审难以覆盖 | 十个切片各自独立提交、各自带断言；评审按切片分组审 | 逐片 revert |
