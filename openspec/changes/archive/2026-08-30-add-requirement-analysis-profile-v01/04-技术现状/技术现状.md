# 技术现状

## 已有能力

- `openspec/profiles/registry.json` 注册 `delivery-change` 和 `light-change`。
- `workflow-core.ts` 以线性阶段前缀执行 profile，支持 `blocked`、`waiting_human_judgment`、`in_progress`、`completed` 和 `rejected`。
- `workflow-control.ts` 提供 `list-profiles`、`bind` 和 `run`；Change binding 固定 profile 身份和版本。
- profile stage 当前只有 `id`、`displayName`、`requiredInputs` 和 `humanJudgment`，不能表达分析循环、人工判断选项或输出投影。

## 技术缺口

1. 需要可选的 stage judgment options，拒绝未知人工判断值。
2. 需要可选的 repeat judgments，使 `clarify`、`discover` 和 `evaluate` 在 `continue-analysis` 时保持当前阶段。
3. 需要可选的 output inputs，把问题框架、能力核验、方案比较和决策结果投影到机器结果。
4. 需要将需求分析 profile 从单一 analysis 阶段扩展为五阶段顺序合同。
5. 需要新增 profile fixture、CLI 场景和回归测试。

## 约束

- 保持现有 request/result 顶层合同兼容。
- 不引入 Desk 读取、跨仓扫描、持久化平台或自动建 Change。
- profile registry、schema 和公开清单必须同步。
