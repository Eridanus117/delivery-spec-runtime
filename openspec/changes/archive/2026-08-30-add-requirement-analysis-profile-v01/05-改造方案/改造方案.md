# 改造方案

## 合同改造

1. 扩展 `WorkflowStage` 与 `workflow-profile.schema.json`：增加可选人工判断选项、重复判断值和输出输入键。
2. 保持旧字段和旧 profile JSON 不变；解析器仅对新字段执行校验。
3. 执行器在当前阶段收到重复判断值时返回 `in_progress`、`nextStageId=currentStageId`，不追加完成阶段；该语义复用于 `clarify`、`discover` 和 `evaluate`。
4. `decision` 阶段的 `outputInputs` 投影完整问题框架、能力核验、方案比较和决策结果。

## Profile 与注册

1. 新增 `openspec/profiles/requirement-analysis-v1.json`，定义五阶段顺序合同。
2. 注册到 `openspec/profiles/registry.json`。
3. 将 profile 和合同加入公开清单。

## CLI 与文档

- 复用 `workflow list-profiles` 显示新 profile 的完整阶段合同。
- `workflow run` 沿用显式 Change binding、request 文件和结果文件。
- 在 workflow guide 中说明需求分析 profile 的用途、循环调用方式和 Desk 边界。

## 不做

- 不读取 Desk 或其他仓库。
- 不自动创建 Change、绑定后续 profile 或写入调用方资产。
- 不实现任意阶段回退、复杂 DAG、门 C 复盘和跨仓索引。
