# 测试计划

## 验证范围与层级

| 层级 | 目标 | 工具/入口 | 通过标准 |
|---|---|---|---|
| 合同层 | 校验 profile、binding、request、result 和 registry 的字段、版本及未知字段拒绝 | `node --experimental-strip-types` + 合同解析器 | 合法合成 fixture 全部通过；缺字段、未知字段、重复身份和非法版本均非零失败 |
| core 行为层 | 验证 profile 解析、Change 绑定、版本固定、阶段推进和阻塞结果 | `test/workflow.test.ts` | 两个 profile 的阶段、结果和下一步互不混淆；拒绝、阻塞和人工判断不伪装为完成 |
| 真实 CLI 层 | 验证统一入口转发、stdout JSON、退出码和显式输入边界 | `workflow-control.ts`、`runtime-entry.ts workflow ...`、`runner/*.ts` | `list-profiles`、`bind`、`run` 均使用显式路径和 binding；成功、阻塞、拒绝分别满足输出与退出码合同 |
| 运行时边界层 | 验证 consumer submodule、gitlink、manifest、软链和旧 delivery 路径不回归 | `test/submodule.test.ts`、临时 consumer fixture | dirty submodule、gitlink 漂移、软链漂移和缺失绑定均 fail closed；旧 `runtime-check` 与 lifecycle 行为保持通过 |
| 兼容与文档层 | 验证 `delivery-change` 仍是独立重型 profile，公共文档和命令渲染物一致 | `test/*.test.ts`、`render-commands.ts check`、`openspec validate --all --strict` | 不增加第二套 lock/hash 或 manifest 软链；九个 Commands 无渲染漂移；严格校验通过 |

## 测试环境与数据

| 资产 | 位置 | 生命周期 | 清理责任 |
|---|---|---|---|
| 合成 profile registry | `06-测试方案/fixtures/profiles/` | 测试运行期间只读 | runner 结束删除临时复制物 |
| 合成 Change binding | `06-测试方案/fixtures/bindings/` | 测试运行期间只读 | runner 结束删除临时复制物 |
| 合成 workflow request/result | `06-测试方案/scenarios/` | 随测试源码版本化 | 只保留公共、无业务含义的最小样例 |
| CLI probe | `06-测试方案/runner/` | 测试运行期间执行 | 不写入真实消费仓；临时目录由 runner 清理 |
| 临时 Runtime/consumer Git fixture | 系统临时目录 | 单次测试创建 | `finally` 清理；父仓和 submodule 在清理前均断言无意外写入 |

测试只使用稳定的公共 profile id、版本、阶段名和合成事项身份。不得读取全局索引、账号、凭据、真实项目路径或未授权外部资产；请求必须显式携带 registry、Change binding、matter identity 和输入。

## 场景与 Requirement 覆盖

| 场景 ID | Requirement | 前置 | 输入 | 断言 | 清理 |
|---|---|---|---|---|---|
| PF-001 | 多 profile 识别 | registry 含 `delivery-change@1.0.0` 与 `light-change@1.0.0` | `list-profiles` | 返回两个稳定 `profileId`、版本和阶段合同；阶段集合无交叉污染；结果可按身份排序 | 删除临时 registry |
| PF-002 | profile 身份冲突 | registry 同时含相同 `profileId@version` 的不同内容 | registry load | 非零退出并明确冲突；不得覆盖先出现的定义 | 删除冲突 fixture |
| PF-003 | 显式绑定 delivery profile | registry 可解析 `delivery-change@1.0.0` | `bind` 请求 | binding 保存且回显精确 id/version；不复制 profile 正文 | 删除临时 binding |
| PF-004 | 显式绑定第二 profile | registry 可解析 `light-change@1.0.0` | 第二个 Change 的 `bind` 请求 | 第二个 Change 的 binding 与 delivery 独立；后续结果不出现 delivery 阶段或 artifact | 删除临时 binding |
| PF-005 | 缺失或未知 binding | request 缺 `profileId`、缺 `profileVersion`，或引用未注册版本 | `run` 请求 | 显式拒绝；非零退出；不得按目录、标题或默认规则补全 profile | 删除临时 request |
| PF-006 | 版本固定 | 同一 Change 已绑定 `light-change@1.0.0`；registry 另增 `light-change@2.0.0` | 连续两次 `run` | 两次结果均回显 `light-change@1.0.0`；不得静默切换；若原版本被移除则返回版本缺失的阻塞或拒绝 | 删除临时 registry |
| PF-007 | 阶段推进与结果合同 | 两个 profile 均有可执行的合成阶段 | `run` 带显式当前状态和输入 | 返回 machine-readable `status`、当前阶段、下一步、binding 和产物入口；成功结果只在满足退出条件时产生 | 删除临时状态 |
| PF-008 | 缺输入阻塞 | 当前阶段声明必需输入但 request 未提供 | `run` 请求 | `status=blocked`，原因稳定且指出缺失输入；不得标记 `completed` 或 `PASS` | 删除临时 request |
| PF-009 | 人工判断等待 | 当前阶段声明人工判断点但 request 未提供判断 | `run` 请求 | `status=waiting_human_judgment`，保留 profile 绑定和阶段；不得自动通过 | 删除临时 request |
| PF-010 | 独立调用与无外部状态 | 临时 consumer 无全局索引和外部配置 | 通过 `runtime-entry.ts workflow list-profiles|bind|run` 调用 | stdout 为单个可解析 JSON；consumer 父仓、未授权目录和 Runtime 源树内容不变；不生成第二套 lock/hash | 删除临时 consumer 与 Git fixture |
| PF-011 | 统一入口安全校验 | consumer 使用固定 commit submodule 和三条相对软链 | workflow 命令；再分别制造 dirty、gitlink、manifest、软链漂移 | 所有 workflow 命令先失败于既有 Runtime 检查；不得绕过旧 fail-closed 门禁 | 恢复或删除临时 fixture |
| PF-012 | 既有 delivery-change 兼容 | 既有 delivery Change 和旧 lifecycle fixture | `runtime-check`、旧 lifecycle inspect/guard、旧合同测试 | 旧入口结果与新增 profile 代码无关；旧 artifact、锁、版本 pin 和 submodule 状态不变 | 删除临时 Change |
| PF-013 | 失败隔离 | 故意提供非法 profile 或 workflow request | 先执行失败的新 workflow，再执行旧 delivery 命令 | 新入口失败不修改旧合同、不放宽旧校验；旧入口仍可成功或按原规则失败 | 删除临时 fixture |
| PF-014 | 合同和渲染回归 | Runtime 源仓和命令真源完整 | `render-commands.ts check`、全量合同测试、严格校验 | 九个 Commands `changed=[]`；合同测试通过；`openspec validate --all --strict` 通过 | 删除所有临时输出 |

## 自动化资产

```text
06-测试方案/
├── fixtures/
│   ├── profiles/
│   ├── bindings/
│   └── requests/
├── scenarios/
│   ├── profile-selection.json
│   ├── profile-conflict.json
│   ├── version-pinning.json
│   └── blocked-and-waiting.json
├── runtime/
│   └── consumer-fixture.ts
└── runner/
    ├── workflow-cli-probe.ts
    └── workflow-boundary-probe.ts
```

- TypeScript runner 使用 `node --experimental-strip-types`，并以 `process.execPath` 启动真实 CLI；不得以字符串匹配源码代替行为断言。
- CLI 成功请求断言零退出码和单个 JSON；阻塞、等待、拒绝断言非零退出码、可解析结果和稳定 `reason`。
- 每个测试记录创建的临时根，并在 `finally` 中清理；清理前比较 consumer 父仓、Runtime submodule 和受管软链的前后状态。
- fixture 只保存公共合成数据；不保存真实工作需求、账号、凭据、环境、请求响应、trace、run-id 或 release-id。

## 失败停止条件

出现以下任一情况，runner 立即失败，不继续执行后续场景：

1. `runtime-entry.ts runtime-check` 非零；
2. workflow 命令在缺失或未知 binding 时成功；
3. profile 新版本导致已绑定 Change 静默切换；
4. blocked 或 waiting 结果被标记为完成；
5. workflow 命令绕过 manifest、gitlink、submodule dirty 或软链校验；
6. consumer 或未授权路径出现写入；
7. 旧 `delivery-change` 命令、合同测试或严格校验回归；
8. 清理阶段发现临时资产、锁文件或测试证据未删除。

```bash
node --experimental-strip-types --test test/workflow.test.ts
node --experimental-strip-types --test test/*.test.ts
node --experimental-strip-types openspec/tools/render-commands.ts check --runtime-root .
openspec validate --all --strict
```

本文件只定义测试策略、场景和通过标准，不记录实际运行结论。实际结果必须写入后续验收制品及其受管运行证据。
