- 先解决输入池身份和格式可见性，再让 Workflow 取事项，避免 Agent 对重复或 legacy 记录自行猜测。
- 只读清单、重复分组和 legacy 报告可以复用现有路径守卫，并保持单文件写入命令不变。
- 候选 B 直接满足 `intake-workflow` 对 legacy inspect 的结构化迁移缺口要求，且不替维护者决定业务归属。
- 该切片可独立验证、可独立回滚，不引入自动路由、数据库、远程 telemetry 或并发策略。

## 接受的后果

- `intake-control.ts` 会新增只读清单和 legacy 报告语义；依赖旧失败文本的调用方需要接受结构化诊断。
- 重复 ID 不会被自动修复；维护者仍需明确选择迁移、重命名或关闭路径。
- 清单只提供确定性输入和诊断，不负责业务优先级和自动创建 Change。
