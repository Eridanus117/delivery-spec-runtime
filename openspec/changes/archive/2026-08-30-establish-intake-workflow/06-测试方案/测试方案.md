# 测试计划

## 验证范围与层级

| 层级 | 目标 | 工具/入口 | 通过标准 |
|---|---|---|---|
| Schema contract | 校验 Intake state、phase、history 和引用字段 | Node `node:test` + JSON Schema fixture | 合法样例通过；未知键、非法枚举、坏日期和缺字段拒绝 |
| Core transition | 校验 DAG、输入门和历史不变量 | 直接调用 `intake-control.ts` 导出函数 | 只允许合法后继；失败不改变文件 |
| CLI behavior | 校验真实 `runtime-entry.ts intake ...` 命令 | `runTool` 临时仓 | init、inspect、advance、hold、close、reopen、promote 输出和退出码符合合同 |
| Security/path | 校验路径越界和 Runtime 绑定保护 | 临时 repo/submodule fixture | Runtime root、submodule、绝对越界路径和 dirty 状态 fail closed |
| Regression | 确认旧 workflow、delivery lifecycle 和 Commands 不变 | 现有 `test/*.test.ts` | 既有测试保持通过 |

## 场景与 Requirement 覆盖

| 场景 ID | Requirement | 前置 | 输入 | 断言 | 清理 |
|---|---|---|---|---|---|
| I-001 | machine-readable lifecycle | 临时项目根 | 合法 init 参数 | 生成标准 frontmatter 和模板章节 | 临时根 |
| I-002 | missing metadata | 手工坏文件 | 缺 `phase`/`source` | inspect/advance/promote/close 非零，文件摘要不变 | 临时根 |
| I-003 | sequential DAG | 合法 Intake | 逐步补齐阶段输入 | 只能按 capture→triage→evidence→options→disposition 推进 | 临时根 |
| I-004 | skipped phase | capture Intake | 直接 advance 到 evidence | 非零，原文件 digest 不变 | 临时根 |
| I-005 | evidence distinction | triage Intake | facts/unknowns/evidence | facts、unknowns 和 evidence 分栏保存，不自动合并 | 临时根 |
| I-006 | candidate vs decision | options Intake | 多候选无 disposition | promote 非零，不创建 Change | 临时根 |
| I-007 | promote | disposition promote + 已存在 Change | `--change-root` | 两侧来源引用存在，Intake state=promoted 且只读 | 临时根 |
| I-008 | invalid promote target | disposition promote | 不存在或越界 Change | 非零，无任何目标写入 | 临时根 |
| I-009 | hold/reopen | disposition hold | hold reason + reopen | 状态为 held，历史保留，reopen 回 triage | 临时根 |
| I-010 | close/reopen | disposition close | close reason + reopen | closed 保留原因，重新经过 DAG | 临时根 |
| I-011 | legacy inspect | status-only Intake | 无 schema/phase | 返回 legacy 和缺口，不改文件、不允许 promote | 临时根 |
| I-012 | path protection | Runtime/submodule fixture | Intake root 指向受保护路径 | fail closed，submodule dirty 状态和文件摘要不变 | fixture |
| I-013 | sensitive content | 合法临时 Intake | 凭据、绝对路径、机器标识或响应全文 | 拒绝保存或要求脱敏，公共资产无敏感值 | 临时根 |
| I-014 | consumer no-write | 临时 consumer + Runtime fixture | 执行 inspect/advance/promote | Runtime 仓和未授权 consumer 路径前后摘要一致 | 临时根 |

## 自动化资产

```text
06-测试方案/
├── fixtures/
├── scenarios/
├── runtime/
└── runner/*.ts
```

- TypeScript runner 使用 `node --experimental-strip-types`。
- 测试只使用合成 Intake 和临时仓；不把真实业务输入、账号、环境或请求响应写入仓库。
- 文件状态断言使用 digest/摘要和 Git 状态，不依赖机器绝对路径。
- 每个 CLI 行为探针断言 stdout JSON、stderr、退出码和副作用；失败时立即终止该场景。
- 在最终验证前运行 `openspec validate --all --strict` 和现有 Runtime 合同套件。
