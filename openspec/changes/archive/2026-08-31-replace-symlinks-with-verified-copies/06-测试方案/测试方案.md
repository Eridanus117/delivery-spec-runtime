# 测试计划

## 验证范围与层级

| 层级 | 目标 | 工具/入口 | 通过标准 |
|---|---|---|---|
| 投影建立 | apply 产出普通文件副本、原子替换、幂等 | `test/submodule.test.ts` 扩展 | 副本非软链、内容与源逐字节一致、重复 apply 结果不变 |
| 漂移拒绝 | 改/删/增任一文件、整体替换均被 runtime-check 拒绝 | 同上 | 非零退出且错误含漂移投影路径 |
| 迁移语义 | 旧软链自动替换；不一致非链内容需 `--replace-managed`；一致内容放行 | 同上 | 三种前置分别得到预期行为 |
| 升级采样 | fingerprint 改内容摘要后升级评估合同不变 | `test/openspec-upgrade.test.ts` | 既有断言全过，报告字段不变 |
| 措辞一致 | preamble/命令体/文档不再以软链描述受管路径 | `render-commands.ts check` + contracts 断言 | check 归零；断言匹配新措辞 |
| 全量回归 | 既有合同不受影响 | LF 克隆 `test/*.test.ts` + strict validate | 全过，无断言放宽 |

## 测试环境与数据

沿用既有 fixture 风格：临时 git 仓 + submodule + apply；无网络、无真实业务数据；临时目录 `t.after()` 清理。

## 场景与 Requirement 覆盖

| 场景 ID | Requirement | 断言要点 |
|---|---|---|
| VC-001 | plain-file copies verified | 四条投影存在、`isSymbolicLink()===false`、抽样文件字节等于 submodule 源 |
| VC-002 | 副本漂移被拒绝 | 修改一个文件 → check 非零且指名路径；删除文件、新增文件同理 |
| VC-003 | gitlink 唯一锁 | 升级 gitlink 未重跑 apply → check 拒绝；重跑后通过；全仓无新增哈希清单文件 |
| VC-004 | legacy migration | 手工造旧软链 → apply 静默替换为副本 → check 通过 |
| VC-005 | replace-managed 门槛 | 受管路径写入不一致普通内容 → apply 拒绝；`--replace-managed` 后修复 |
| VC-006 | 无 symlink 能力接入 | fixture 全程不依赖 `core.symlinks`（克隆参数移除后仍通过） |
| VC-007 | 兼容回归 | 全量测试 + render check + strict validate |

## 断言与停止条件

- 任一漂移形态（改/删/增/换形态）未被拒绝即停止。
- 任何资产中出现固化哈希清单/第二版本记录即停止。
- 既有测试放宽断言即停止。

## 运行命令

```bash
node --experimental-strip-types --test test/submodule.test.ts
node --experimental-strip-types --test test/*.test.ts
node --experimental-strip-types openspec/tools/render-commands.ts check --runtime-root .
openspec validate --all --strict
```
