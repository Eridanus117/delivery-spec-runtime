# 需求理解

## 目标

将当前单一 README 中混合的仓库介绍、架构、消费仓接入、Runtime 维护、受控升级和自治理内容拆成稳定入口与五份专题文档，使不同读者能够按任务阅读。

## 读者与任务

- 新采用者：理解用途并完成最短接入。
- 消费仓维护者：接入、克隆、更新 gitlink、诊断和恢复。
- Runtime 维护者：修改 Commands、schema、contracts，并完成验证。
- 升级执行者：隔离评估并提升 OpenSpec 版本。
- Change 维护者：执行 Runtime 自治理和 fresh session Review。

## 范围

- 重写 README 为入口页。
- 新增 `docs/` 下五份专题文档。
- 明确信息真源边界。
- 保留现有命令、路径、安全规则和可执行示例的含义。
- 由主会话派发 fresh reviewer session 独立审查本次实现。

## 非范围

- 不修改 Runtime 工具、schema、contracts、Commands 或 manifest 行为。
- 不改变消费仓 gitlink 和软链合同。
- 不引入文档站、生成器或新的依赖。

## 澄清结论

- README 是入口，不再承载完整专项 runbook。
- `docs/` 是当前使用和维护说明；`openspec/specs/` 是长期规范；`openspec/changes/archive/` 仅是历史证据。
- 机器合同仍以 JSON、schema 和工具校验为准，文档只解释和链接。
