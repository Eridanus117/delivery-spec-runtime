# 任务 4.1 验证证据

## 交付物

- `openspec/schemas/delivery-change/schema.yaml` 的 `raw-requirements` instruction：删去「并同步维护 `change-sources.json` 机器合同」，改为明确声明「材料索引表的 RAW 编号顺序即来源权威顺序：RAW-001 权威最高，编号越大权威越低。冲突时以编号更小的来源为准，因此录入时就要按权威从高到低编号，不要按拿到材料的先后编号」。
- `openspec/schemas/delivery-change/templates/raw-requirements.md`：材料索引表上方加同义引言块，并写明「全序信息由本表承载，不另设权威列」。

不新增权威列，是因为索引表本来就按 RAW 编号排列，再加一列是同一信息的重复表达；重复表达一旦与编号不一致，就又多出一处需要裁定权威的分叉。

## 覆盖度自检记录（B2 裁定的 fail-closed 前置条件）

裁定 B2 要求：移除 `change-sources.json` 之前，必须逐项确认 `01-原始需求索引.md` 覆盖同等信息；若某类信息只在前者里有，先并入索引再移除。以本 Change 自身的 `change-sources.json`（6 条来源，字段集 `id` / `kind` / `authority` / `locator` / `adapter`）逐字段核对：

| change-sources 字段 | 01 索引中的对应表达 | 覆盖判定 |
|---|---|---|
| `id`（RAW-001…006） | 材料索引表的 **ID 列**，同名同值 | 完全覆盖 |
| `kind`（`intake-item` / `maintainer-confirmation`） | 材料索引表的 **来源列**（「Intake INT-20260831-019」「Runtime 维护者 2026-08-31 主会话逐条裁决」） | 完全覆盖，且索引侧信息量更大（带条目号与场合） |
| `locator`（仓内路径或会话标识） | 材料索引表的 **原始位置/附件列**，逐条同值 | 完全覆盖 |
| `adapter`（6 条全为 `manual`） | 无对应列 | **无信息量**：全历史仅取单一常量值，且 adapter 注册表是 `adapter inspect` 的独立机制，与来源表不构成消费关系。不并入 |
| `authority`（1…6 的全序） | 无对应列 —— **唯一的独占信息** | 由本任务立法的「RAW 编号顺序即权威顺序」承接 |

逐条 locator 比对（6/6 一致）：

| ID | change-sources.locator | 01 索引原始位置列 |
|---|---|---|
| RAW-001 | `openspec/intake/INT-20260831-019-three-item-retrospective.md` | 同 |
| RAW-002 | `openspec/intake/INT-20260831-014-calibration-signals.md` | 同 |
| RAW-003 | `openspec/intake/INT-20260830-002-change-profile-routing.md` | 同 |
| RAW-004 | `current-change-session-2026-08-31` | 「当前 Change 创建会话」（语义同指） |
| RAW-005 | `openspec/intake/INT-20260831-007-workflow-usability-and-review-surface.md` | 同 |
| RAW-006 | `openspec/intake/INT-20260830-005-metrics-concurrency.md` | 同 |

**结论**：除 `authority` 外全部信息在 01 索引中已有对应表达；`authority` 的全序语义由新立法的 RAW 编号顺序承接，覆盖度前置条件满足，可以移除。

**一处必须如实记录的语义变化**：本 Change 自身 `change-sources.json` 的 `authority` 排序是 RAW-004 → 001 → 002 → 003 → 005 → 006，与 RAW 编号顺序**不一致**。新规则不追认这份历史排序——它对**新建 Change** 生效，要求录入时就按权威编号。本 Change 是最后一个 v5 结构 Change，其 `change-sources.json` 文件按「存量原样冻结」保留在目录内，不删除也不改写（同 10 个归档目录的处理）。这一点属于「新旧并存」的既定后果，不是覆盖度缺口。
