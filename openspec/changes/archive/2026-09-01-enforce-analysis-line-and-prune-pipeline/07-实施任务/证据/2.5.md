# 任务 2.5 验证证据

## 交付物

- `openspec/tools/runtime-entry.ts`：转发 `intake` 时补 `--runtime-root`。原先只有 `workflow` 得到该参数（`internalArgs = workflow ? [...] : []`），现改为 `workflow || intake`。入口的校验顺序与 fail-closed 语义一字未动——补参数发生在全部校验通过之后的 spawn 参数拼装处。
- `openspec/tools/intake-control.ts`：`promote` 用 `options.get("runtime-root") ?? root` 定位路由表，即消费仓形态下读 Runtime 侧的表，源仓自用时回落到资产根（两者同一目录）。

路由表放 Runtime 侧而非资产仓，是为了避免每个消费仓各自维护一份使规则分叉；消费仓经 `.delivery-spec-runtime` 前缀访问同一张表。

## 验证

- `node --experimental-strip-types --test test/intake.test.ts test/workflow.test.ts test/submodule.test.ts` → 全部通过；`submodule.test.ts` 的入口校验用例（gitlink 漂移、dirty submodule、投影漂移、未初始化）与改造前一致。
- `runtime-entry.ts runtime-check --change-root .` → `{"allowed": true, ...}`。
- 立项门测试通过显式 `--runtime-root` 指向内联最小路由表运行，证明该参数确实被 `intake-control.ts` 消费；未给该参数时回落资产根，仓内自用路径同样可用。
