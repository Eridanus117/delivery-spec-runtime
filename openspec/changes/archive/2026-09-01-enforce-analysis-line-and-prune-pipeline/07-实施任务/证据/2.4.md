# 任务 2.4 验证证据

## 交付物

`openspec/tools/intake-control.ts` 的立项门。`promote` 的执行顺序被重排为「先判后写」：

1. `rejectSelfDeclaredRouting(options)`：命中 `exempt` / `exempt-analysis` / `waive-analysis` / `skip-analysis` / `no-analysis` / `profile-id` / `delivery-tier` / `downgrade` 任一选项即拒绝。
2. 解析条目、校验 phase、解析目标 Change。
3. `loadRouting(runtimeRoot)` 读路由表并校验其合同（含「unmatched 必须是最重档且不豁免」）。
4. `routeFor(routing, changeObject)`：条目的 `changeObject` 来自其自身 frontmatter；未声明或表内未命中即取 `unmatched`。
5. 若 `requiresAnalysis` 为真，`requireAnalysisLine(root, id)` 校验产物存在、可解析、`binding.matterId` 与 `result.matterId` 均等于条目 id、`status=completed`、`outputs.disposition=build`。
6. 以上全部通过后才开始写盘。

`changeObject` 作为**可选**兼容字段加入 frontmatter，由 `intake init --change-object` 在登记时写入。它不进 `requiredFields`，故 20 条存量条目仍全部 `current`。把类别放在条目自身声明里而不是 promote 的命令行参数上，是为了让它成为台账里可复审的公开声明，而不是过门时的临时说法。
