# 需求理解

## 目标

把 OpenSpec 升级从“对实时仓运行官方 update”改成 Runtime 仓内可重复的候选评估流水线。流水线先隔离生成，再比较上游与本地差异，验证机器 CLI 合同和消费仓兼容性，最后才决定是否提升 Runtime pin。

## 本 Change 范围

1. 将九个 Runtime Commands 拆为公共 preamble、九个 body fragments 和版本化 manifest，并提供确定性 renderer/check。
2. 提供 `openspec-upgrade.ts evaluate`，以严格 JSON 请求驱动 current/candidate 隔离生成和机器报告。
3. 定义并执行长期 OpenSpec CLI JSON probes。
4. 在临时 Git fixture 中执行空白项目和三个消费仓 smoke，真实仓保持只读。
5. 实际评估 `1.10.0 → 1.11.0`；只有完整门禁通过才吸收写入确认和配置文件范围，并将上游 plain ASCII 意图按 OMP 能力适配为 Mermaid，随后提升 manifest pin。
6. 重写 README 为采用者/维护者入口，并更新 Runtime public candidate allowlist、合同测试和 Change 验收证据。

## 不在范围

- 不恢复实时仓 `runtime-update`。
- 不更新 `agent-system`、`webcoding-spec` 或 `work-spec` 的 Runtime gitlink。
- 不建立常驻服务、自动定时升级、自动合并 PR 或远程发布机器人。
- 不把消费仓业务内容复制到 Runtime 证据。
- 不承诺任意未来 OpenSpec 版本自动兼容；每个实际版本升级仍需独立 Change 和明确 candidate version。

## 术语

- **upstream current**：current 版本官方生成的 OMP Commands。
- **upstream candidate**：candidate 版本官方生成的 OMP Commands。
- **Runtime current**：当前 fragments 确定性渲染结果。
- **Runtime candidate**：吸收候选上游规则后的 fragments 渲染结果。
- **upstream delta**：upstream current 与 upstream candidate 的差异。
- **current-local delta**：upstream current 与 Runtime current 的差异。
- **candidate-local delta**：upstream candidate 与 Runtime candidate 的差异。
- **probe**：声明 argv、期望退出码和 required fields 的机器 CLI 合同。
- **消费仓 smoke**：在临时副本中注入候选 Runtime/CLI 后执行的只读兼容性验证。

- OMP 支持 Mermaid，因此结构、流程、状态和依赖图优先使用 `mermaid` fenced block。ASCII 只作为不支持 Mermaid 的外部目标降级，不在 OMP Command 中保留 Unicode 线框示例。

## 关键解释

- `.omp/commands` 仍是消费仓暴露路径；变化的是 Runtime 仓内部维护方式，不改变消费仓链接合同。
- fragments 不是把九个 Commands 再复制一遍。公共 Runtime 入口和重复防护只保留在 preamble；每个 fragment 只保存命令独有正文。
- 官方生成结果是对比输入，不是 Runtime 真源。评估器不得把它直接覆盖到 `.omp/commands`。
- “候选通过”同时要求生成结果、差异报告、JSON probes、renderer、Runtime 全量合同和三仓 smoke 通过，不能只凭 1.11 release note 判断。

## 交付边界

本 Change 使用分支 `change/establish-controlled-openspec-upgrades` 和独立 PR。前置安全 Change 已合并；本 Change 不修改其 fail-closed 结论。
