# 原始需求索引

## Change 意图

在 `delivery-spec-runtime` 建立可重复、可审计、不会写入实时消费仓的 OpenSpec 升级能力，并用该能力实际评估 `1.10.0 → 1.11.0`。候选版本只有在命令渲染、CLI JSON 合同、Runtime 合同和三个消费仓隔离 smoke 全部通过后才能进入 Runtime。

## 原始来源

### RAW-001 维护者决定

- 来源：`maintainer-session`
- 原文口径：Runtime 使用仓内 OpenSpec 与版本化文档治理自身演进；升级框架作为第二个独立 Change；所有代码通过功能分支和 PR 交付，不直接推默认分支。
- 已确认能力：current/candidate 隔离生成、上游/本地 delta、fragments 与 rendered Commands、CLI JSON 合同、多消费仓 smoke、实际版本评估。

### RAW-002 已合并安全前置

- 来源：`runtime-repository`
- 证据：`openspec/changes/prevent-live-runtime-update-mutation/`、PR #1 合并提交 `b8efa99f4adf3d735e19007b2ab3d9739fead433`。
- 事实：实时资产仓的 `runtime-update` 已在调用 OpenSpec CLI 前 fail closed；后续升级能力不得重新开放原地生成路径。

### RAW-003 Runtime 当前实现

- 来源：`runtime-repository`
- 当前 pin：`runtime-manifest.json` 要求 OpenSpec `1.10.0`。
- 当前定制：九个 `.omp/commands/opsx-*.md` 相对上游 1.10 均为大幅整文件定制；单文件差异达到 39～222 行删除、59～203 行新增，不能依赖官方 update 或脆弱的小补丁维护。
- 当前公开候选：`public-candidate.ts` 以 allowlist 控制可发布 Runtime 树；新增工具、合同和 fragments 必须显式纳入。

### RAW-004 OpenSpec 官方更新写入语义

- 来源：`openspec-v1.11-update-source`、`openspec-v1.11-omp-adapter`
- `src/core/update.ts` 遍历集成目标并直接写入生成文件。
- OMP adapter 固定生成 `.omp/commands/opsx-<id>.md`。
- 结论：current/candidate 只能在隔离根生成；禁止把真实消费仓或 Runtime checkout 作为官方生成器 cwd。

### RAW-005 OpenSpec 1.11 候选事实

- 来源：`openspec-v1.11-release`、隔离临时探针。
- 1.10 与 1.11 均生成九个 OMP Commands，文件集合相同；上游差异仅涉及 `opsx-explore.md`。
- 1.11 的 explore 规则新增：写入前单独明确确认、plain ASCII 图、配置文件也属于写入范围。
- 1.11 新增 `show --diff`、`status --all`，并修复 `schema init --default`。
- 1.10 与 1.11 对当前 `delivery-change` 的 `status --change --json` 均成功，观测到的 JSON 结构一致。

### RAW-006 维护者对 README 与图示的纠偏

- 来源：`maintainer-session`
- 维护者判断：当前 README 结构和表达质量不足，不能继续以追加零散段落的方式维护。
- OMP 原生支持 Mermaid；Runtime 的 OMP 专用 `opsx-explore` 应使用 Mermaid 表达真实结构、状态、流程和依赖，不应机械照搬上游 plain ASCII 偏好。
- 交付要求：README 重写为面向采用者和维护者的入口，明确架构、边界、接入、不变量、受控升级请求/报告和验证；示意架构使用 Mermaid。

## 冲突与边界

- “升级”不是在实时仓执行 `openspec update`，而是在隔离根生成、比较、验证后通过 Runtime PR 交付。
- 不能把九个整文件直接复制为第二份长期真源；fragments、公共 preamble 与 manifest 必须成为唯一可维护源，`.omp/commands` 是确定性渲染物。
- 上游 1.11 的 plain ASCII 变化是待审输入。OMP 渲染面优先 Mermaid；只有目标表面不能渲染 Mermaid 时才使用简洁 ASCII，且禁止 Unicode 线框字符。
- 本 Change 必须真实评估 1.11，但不得预设升级结论；门禁失败时保持 pin `1.10.0` 并保存失败证据。
- 本 Change 不更新任何消费仓 gitlink，不读取或保存消费仓业务 Change 正文、环境、凭据或私人材料。
