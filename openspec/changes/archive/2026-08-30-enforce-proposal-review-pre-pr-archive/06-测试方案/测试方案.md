# 测试方案

## 测试目标

证明新生命周期具备四个性质：方案选择显式、Review 覆盖且可失效、Archive 只在同步和验收完成后放行、PR 反馈可恢复而不覆盖历史。

## 永久合同测试

### T-01 Schema v5 Artifact 顺序

- `openspec status --change <fixture> --json` 必须返回 Proposal→Decision→Plan 依赖。
- 缺少 Proposal 或 Decision 时后续 artifact 不得 ready。
- 三项批准 digest 独立；修改 Proposal 只使 Proposal 及其下游批准 stale。

### T-02 Proposal 与 Decision 质量门禁

- Proposal 缺少候选、Trade-off、推荐或未决问题时 `guard apply` 拒绝。
- Decision 缺少 APPROVED、选择、决策人、时间、拒绝方案或接受后果时拒绝。
- 只批准 change-plan 不能绕过 Proposal/Decision。

### T-03 Review 完整覆盖

- 临时 Git fixture 在 baseline 后修改多个实现路径。
- reviewedPaths 精确覆盖时可写入；缺失、额外、绝对路径、`..`、逃逸软链分别拒绝。
- 当前 Change 规划目录、归档证据和主 specs 不计入实现路径。

### T-04 Review finding 与 stale

- OPEN CRITICAL/HIGH 或任意未处置 finding 不能 PASS。
- 路径内容、删除状态或 HEAD 在 Review 后变化时 inspect 非零并报告 stale。
- Reviewer、时间、commit 和聚合 digest 使用严格 exact-key 合同。

### T-05 Acceptance 内容寻址

- tasks 全 verified、Review PASS 且验收正文严格 PASS 时生成 Acceptance State。
- Review、task state、验收正文或 accepted commit 任一变化后 acceptance guard 拒绝。
- 单独写 `结论: PASS` Markdown 不再足以放行。

### T-06 Archive Readiness

- delta/main spec 映射、摘要、strict validation、cleanup 证据和 `prStarted=false` 齐全时 READY。
- `prStarted=true`、缺失 spec、摘要漂移、cleanup FAIL、旧 Acceptance 分别拒绝。
- 09 出现 `release-not-required` 但没有 READY 时 archive guard 必须拒绝，覆盖旧 fail-open。

### T-07 Reopen

- 构造 archived Change，执行 reopen 后目录恢复 active。
- 旧 Review/Acceptance/Readiness 与 08/09 保存在唯一 lifecycle-history 快照。
- 当前 PASS 状态被移除，任务回到 `implemented_unverified`。
- 目标冲突、dirty worktree、无有效归档状态、路径越界分别 fail closed。

### T-08 Commands 和 README 顺序

- `/opsx-propose` 明确 Proposal 不能自动作最终决定。
- `/opsx-verify` 写入持久化 Review，而不是只输出聊天报告。
- `/opsx-archive` 固定 Sync→Readiness→Archive→Final Validation→PR 顺序，不允许跳过 sync。
- README Mermaid 明确 Archive 在 PR 前；消费仓升级独立。

### T-09 Public Candidate

- 新模板、状态 schemas 和治理工具在 public allowlist。
- 禁用路径、秘密、熵和 provenance 检查继续通过。

### T-10 历史迁移边界

- 正常 Change 禁止 historical PR 字段。
- 只有显式 `migrationSource=pre-v5-merged-change` 和维护者批准时允许历史补归档。
- 迁移记录必须保留原 PR 早于 Archive 的事实。

## 实施后 Review

本 Change 自身采用新合同完成：

1. baseline 为本分支创建点 `origin/master`；
2. reviewed commit 为实现和永久测试提交；
3. reviewedPaths 覆盖除当前 Change 目录、主 specs 和验收证据外的全部变更；
4. findings 全部处置后结果才可 PASS；
5. Acceptance 绑定 Review；
6. Sync delta spec 后写 Readiness；
7. 归档并 final validate；
8. 最后创建 PR。

## 清理

- 所有 Git 和 Change fixture 使用临时目录并在 `finally` 删除。
- Reopen 测试只操作临时仓库。
- 不创建远端、不推送、不访问消费仓真实 Change。
