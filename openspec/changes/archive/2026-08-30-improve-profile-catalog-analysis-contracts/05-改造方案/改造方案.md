# 改造方案

## 1. 扩展 Profile 合同

- 为 Profile 增加 `purpose`、`recommendedFor`、`notRecommendedFor`、`handoff`。
- 为阶段增加 `description` 与 `exitCondition`。
- 增加声明式 `inputContracts`，支持 object requiredFields、array itemRequiredFields、enum 和可选字段。
- 给 `requirement-analysis` 声明报告和 `analysisRounds` 合同；将 `analysisRounds` 纳入分析阶段必需输入。

## 2. 增加查询命令

- `workflow catalog`：按 registry 顺序输出所有 Profile 的人读 Markdown 摘要。
- `workflow describe --profile-id ... --profile-version ...`：输出单个精确 Profile 的完整摘要。
- `workflow list-profiles` 保持原 JSON 合同和行为。

## 3. 执行校验

- 在通用 core 中对当前阶段及已完成阶段检查 input contract。
- 对 `judgments` 继续执行原有人工判断和循环规则。
- 对 `disposition` 和候选 Profile 执行声明式枚举/字符串校验。
- `publishedInputs` 增加通过 Profile 声明的分析轮次。

## 4. 兼容与交接

- 既有 Profile 增加元数据和阶段说明，但不改变阶段顺序及合法请求的状态转移。
- `build` 仍只返回调用方可执行的候选 Profile，不创建 Change。
- Desk 或项目仓自行保存分析记录和调用结果。
