# 原始需求资产

## 变更入口

- Change：`improve-profile-catalog-analysis-contracts`
- 需求方：Runtime 维护者
- 来源：当前会话中对既有多 Profile Workflow 设计的复盘与改进决定
- 原始描述：需要有清晰办法知道当前有哪些 workflow、每个 workflow 的阶段和流程；需求分析流水线要能真正保存分析轮次和报告内容，而不是只检查几个输入键。

## 已确认边界

- `delivery-change`、`light-change` 和 `requirement-analysis` 继续作为独立 Profile。
- Desk 的个人策略、事项归属和总仓索引不进入 Runtime。
- Runtime 不自动读取或写回 Desk，不自动创建 Change，不自动替主人通过决策门。
- 本 Change 只增强公共 Runtime 的 Profile 说明能力和需求分析输入/输出合同。

## 交付目标

1. 从同一份 Profile 真源生成机器可读和人类可读的 Profile catalog/describe 输出。
2. 明确每个 Profile 的用途、适用/不适用范围、阶段说明、退出条件和交接动作。
3. 为 `requirement-analysis` 的问题框架、能力核验、方案比较、决策报告和分析轮次增加结构检查。
4. 保留已有 Workflow binding、版本固定、阶段顺序和 fail-closed 行为。
