# 业务现状

## 当前使用问题

Workflow System 已经能够列出 Profile，但主要输出机器 JSON。维护者仍需同时阅读 registry、多个 Profile JSON 和专题文档，才能回答“有哪些 workflow、每个阶段做什么、完成后交给谁”。

需求分析 Profile 已有阶段循环和 Gate B，但当前 Runtime 只检查 `requiredInputs` 的键是否存在。调用方可以传入结构不完整的占位值，且分析轮次历史没有公共最小格式。

## Desk 约束

Desk 已裁决：痒点先进入分析循环；需求陈述本身也要被审视；每轮列出已知/未知和证据状态；主人决定何时足够；Gate B 决定建、用现成、缓或不建；建成后由 Gate C 判断留、修或杀。

Runtime 只承载公共阶段和合同。Desk 仍负责个人策略、事项归属、总仓索引和是否调用哪个 Profile。

## 影响

- Profile 选择成本和误用风险增加。
- 需求分析报告质量依赖 Agent 或调用方自律。
- 分析循环虽可运行，但跨轮次复盘和审计格式不统一。
