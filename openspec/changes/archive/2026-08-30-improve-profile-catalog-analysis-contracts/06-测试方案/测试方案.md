# 测试方案

## 合同测试

- Profile schema 接受新元数据、阶段说明和 inputContracts，拒绝未知字段、重复键和非法合同。
- `workflow list-profiles` 保持原 JSON 输出并包含 3 个 Profile。

## Catalog 行为

- `workflow catalog` 输出全部 Profile、用途、阶段和 handoff。
- `workflow describe` 精确输出指定 Profile；未知身份/版本非零退出。
- registry 与 Profile 身份不一致时 catalog/describe fail closed。

## 需求分析行为

- 合法问题框架、能力报告、方案报告、决策报告和 `analysisRounds` 通过并按阶段推进。
- 缺少报告结构字段、占位字符串、非法轮次字段、非法置信度和非法处置值时拒绝。
- `continue-analysis` 保持当前阶段，结果回显累计轮次；`sufficient` 才推进。
- `build` 输出候选 Profile 但不创建 Change、不写 Desk。

## 回归与边界

- `delivery-change` 和 `light-change` 原有 fixture 继续通过。
- 运行 `test/workflow.test.ts`、全部 `test/*.test.ts`、renderer check 和 `openspec validate --all --strict`。
