# 技术现状

- `openspec/profiles/registry.json` 是 Profile 唯一注册表。
- `openspec/profiles/*-v1.json` 保存 Profile 身份和阶段合同。
- `workflow list-profiles` 已加载所有 Profile 并输出 JSON。
- `workflow-core.ts` 目前按阶段检查输入键、人工判断和连续完成前缀；`inputs` 的内容结构为任意 JSON。
- `workflow-result` 通过 `publishedInputs` 回显 Profile 声明的输出键，但没有通用的内容 schema 引用或分析轮次模型。
- `workflow-control.ts` 负责 `list-profiles`、`bind`、`run`；Runtime 入口和消费仓入口共用同一工具。
- 现有三套 Profile 的兼容行为已经由 `test/workflow.test.ts` 和合同测试覆盖。

## 约束

- Node 通过 `--experimental-strip-types` 执行，测试使用 Node 内置 `node:test`。
- Profile registry、Profile 文件、contracts、解析器和测试必须同步。
- Runtime 不读取 Desk，不建立全局扫描或自动建 Change。
- `.omp/commands` 是渲染物，不能手工编辑。
