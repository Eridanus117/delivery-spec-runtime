## 自动化资产

```text
test/
├── contracts.test.ts         # T-PATH-1 / T-PATH-2 / T-IGN-3 / T-COMPAT-1 / T-GUARD-1 / T-GUARD-3
├── submodule.test.ts         # T-LONG-1/2、T-IGN-1/2、T-MODE-1、T-ENTRY-1/2、T-QUIET-1、T-GUARD-2
├── openspec-upgrade.test.ts  # T-SMOKE-1/2
└── helpers.ts                # 临时目录清理的有限退避选项（T-EPERM 缓解）
```

T-IGN-3 与 T-COMPAT-1 直接 import 实现里的 `checkIgnoreIncomplete` 与 `validateReport`，
不在测试里另抄一份判据——`VC-003` 已明令一致性测试不得靠两侧互抄。
判据的 import 来源是 `runtime-lib.ts` 而**不是** `runtime-entry.ts`：后者是受管投影入口，
`main()` 必须无条件执行，一旦被 import 就会连带执行（见改造方案 D-08）。入口里那份逐字副本
由 T-GUARD-1 比对兜底——消费仓的 `openspec/tools/` 下只有 `runtime-entry.ts` 一个文件被投影，
它不能 import 任何同级模块，副本是唯一可行形态，而本仓允许复制的前提一贯是「复制必须可校验」。

T-QUIET-1 落在 `submodule.test.ts` 而非 `control.test.ts`：DEP0190 的产生点是 `runtime-entry.ts` 的版本探测，
而只有 `submodule.test.ts` 里已有以 shim 提供 `openspec --version` 的入口调用夹具；放在别处要重造一套夹具。

- TypeScript 测试使用 `node --experimental-strip-types` 与 `node:test`，不新增 shell runner（AGENTS.md 硬规则）。
- 新增断言一律落在既有测试文件内，不新建 runner 目录；本 Change 无需 fixtures 目录。
- 合成消费仓使用既有 helper 的构造方式，不引入新的夹具体系。

## 失败与停止条件

- 全量测试连跑三次中出现任一次失败：停止，回到 discover 站重新取证，不得以「重跑就好了」收尾。
- `check-ignore` 断言在干净消费仓上误报：停止，该断言下线并重新设计（D-04 的排除逻辑失效即为设计错误）。
- 入口回落导致 T-ENTRY-2 无法与 T-ENTRY-1 区分：停止，回到候选 C。
- 报告合同校验拒绝自身产出的报告：停止，合同与实现必须同批一致。
- 入口出现任何形式的条件执行（按路径写法决定是否跑 `main()`）：停止。这是全体消费仓唯一的 fail-closed 闸门，一旦条件不成立即以退出码 0、零输出静默跳过，失败形状与「跑完且无事发生」无法区分。

## 数据准备与清理

- 全部临时资源由 `mkdtempSync` 创建，测试 `finally` 中删除；删除加有限退避重试。
- 不修改任何非本次运行创建的对象；升级评估已有「真实仓库指纹不变」断言，本 Change 不削弱。
- 清理失败必须使验收结论为 FAIL。
