# 方案决策

## 决策状态

- 状态：APPROVED
- 选择：候选 A：Profile 元数据与内容合同内聚
- 决策人：Runtime 维护者
- 决策依据：当前会话确认“同意”该回顾建议

## 决策内容

1. Profile 文件是阶段与说明的唯一真源；registry 只负责身份和路径索引。
2. 增加人类可读 `workflow catalog` 和精确 `workflow describe`，但保留 JSON `list-profiles` 作为机器接口。
3. 需求分析报告采用声明式最小结构合同，通用 core 负责结构校验，不负责验证事实或替主人判断充分性。
4. 分析轮次作为 request 中的累计 `analysisRounds` 输入，由调用方追加，Runtime 校验并回显，不读取或写回 Desk。
5. Gate B 处置值严格限制为 `build`、`use-existing`、`defer`、`reject`；候选 Profile 仍只是交接建议。

## 不在本 Change

- Desk 自动路由或双向同步；
- 自动创建 Change 或自动绑定下一个 Profile；
- Gate C 的真实使用回顾；
- 全局 Profile 扫描、Web UI 或持久化分析数据库；
- 将 Runtime Core 改成某个 Profile 的专用实现。
