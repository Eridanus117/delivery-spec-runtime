# 任务 1.4 验证证据

## 交付物

`test/station-authority.test.ts` 的 VC-002 段：以真门禁观测值为基准，构造 profile 单边改动的 fixture，断言一致性检查必须报出不一致站位名。

`mismatchedStations(observed, profile)` 是一致性判据的实现：返回 `observed` 与 profile `humanJudgment` 不等的站位名（升序），并把「profile 里没有、观测里有」的站位也计入不一致，故删站同样会被抓住。

## 验证

`node --experimental-strip-types --test test/station-authority.test.ts` → 2 passed / 0 failed。

VC-002 的四条负向断言：

| 单边改动 | 期望 | 结果 |
|---|---|---|
| `archive.humanJudgment` 改回 `true`（即撤销裁定 A3 却不改真门禁） | 报 `["archive"]` | 通过 |
| `review.humanJudgment` 置 `true`（把机器站谎报为人工站） | 报 `["review"]` | 通过 |
| `archive` 与 `review` 同时置 `true` | 报 `["archive", "review"]`，两个都列出而非只报第一个 | 通过 |
| 从 profile 删掉 `sync` 站 | 报 `["sync"]` | 通过 |

即：profile 侧任一单边修改（改标记、删站位）都会使一致性检查非零，且输出直接给出不一致的站位名而不是笼统失败。反向的单边修改（改真门禁不改 profile）由 VC-001 的 `deepEqual` 覆盖——观测值随门禁行为变化，profile 不跟着改即分叉。

结构债因此不会以第二种形态复发：profile 不被废弃，而是降级为人读元数据并被机器钉在真门禁行为上。
